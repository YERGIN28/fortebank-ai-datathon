# Локальный базовый inference

Текущие defaults: refine=False, verify_objects=True. На видео не более трёх
дополнительных проверок cash-кандидатов, по одному кадру до 640 px и с бюджетом
6 секунд каждая. Эти лимиты кооперативные: выполняющаяся операция CUDA/декодирования
может завершиться позже. Неясные/непроверенные предметы не подтверждаются как cash.
Основной ответ — компактный JSON до двух событий на окно, без свободного рассказа;
публичная схема результата сохранена. Дополнительное refine=True — эксперимент.

Предварительный интерфейс, согласованный с Айсаной. Это наблюдения для модуля
правил, а не окончательный контракт backend или заключение о нарушении.

## Использование из Python

```python
from pathlib import Path
from app.inference import InferenceConfig, InferenceEngine

config = InferenceConfig(model_path=Path(r'C:\local\models\Qwen3-VL-2B-Instruct'))
engine = InferenceEngine(config)
engine.load()  # Один раз внутри worker при его старте, до принятия заданий.
result = engine.analyze_video(Path(r'C:\local\input.mov'))
payload = result.to_dict()
```

`analyze_video(path, config)` также доступен как функция. Для нескольких видео
переиспользуйте `InferenceEngine`, чтобы не загружать модель заново. Один engine
обрабатывает один запрос за раз; конкурентный доступ должен ограничивать backend.
На импорте пакета модель не загружается. CUDA обязательна, CPU offload отсутствует.

Модель загружается только из локальной папки, с `local_files_only=True`,
`trust_remote_code=False` и offline-переменными Hugging Face. Код не скачивает веса.
Зависимости указаны в `requirements.txt`; установка выполняется отдельно.

## Результат

- `status`: `complete`, `partial` (ошибочные/непрочитанные окна), `timeout`.
- `observations`: `start_sec`, `end_sec`, `description`,
  `evidence_timestamps_sec`, `timing_resolution_sec`, `refined`, `type`,
  `confidence`, `actors`.
- `processed_windows` / `planned_windows`: успешные / запланированные окна.
- `duration_sec`, `elapsed_sec`, `model_load_sec`, пики памяти PyTorch в MiB.
- `warnings`: технические сообщения без сырых ответов модели и кадров.

Ошибки открытия видео, загрузки модели и CUDA/OOM поднимаются вызывающему коду.
`complete` означает завершённый проход, не доказательство отсутствия нарушений.
Пустые наблюдения при `partial`/`timeout` нельзя считать отрицательным результатом.

`type` допускает `cash_handling`, `cash_transfer`, `cash_left_unattended`,
`cash_drawer_opened`, `cash_drawer_closed`, `document_handling`,
`document_transfer`, `object_transfer`, `unknown`. Это предварительные категории
наблюдаемых действий, а не юридических нарушений; соответствие правилам задаёт Айша.
неизвестная категория приводится к `unknown`. Наблюдение не является нарушением.
`actors` — роли из `cashier`, `customer`, `unknown`, не идентичности людей.
При неопределённости используется `unknown`. `confidence` всегда `null`:
самооценка Qwen не является калиброванной вероятностью, числовые оценки от модели
игнорируются. Базовые поля без новых ключей пока принимаются с defaults unknown/null.

Для backend рекомендуем: незавершённая работа/очередь → `processing`;
`complete` → кандидат на `done` после успешной обработки правилами;
`partial`, `timeout` и исключения → `failed`. Наблюдения partial пригодны только
для предварительного разбора/диагностики, не для финального отрицательного вердикта.
Внешние статусы назначает backend. Инструкция и точный config: `INTEGRATION.md`.

## Обработка и ограничения

Последовательные перекрывающиеся окна: 8 секунд, перекрытие 2 секунды, 4 кадра,
размер до 448 пикселей по длинной стороне. Кадры остаются в памяти; аудио не
декодируется. Таймкоды берутся из PTS видео относительно начала видеопотока,
а не из ответа модели или предположения о постоянном FPS. Отображение поворота
из метаданных MOV пока не поддерживается: для таких файлов нужна доработка.

Сначала выполняется полный грубый проход, затем дополнительная выборка вокруг
наблюдений с контекстом до/после. `refined` означает повторную локализацию,
а не независимое подтверждение исходного события. После прохода и уточнения
консервативно склеиваются одинаковые описания/категории/роли со значимым
перекрытием времени. Для непрерывного удержания допускается соприкосновение
интервалов; две последовательные передачи при простом соприкосновении не склеиваются.
Это эвристика без идентичности участников: семантически разные описания могут
сохранить дубль, а совпадающие описания одновременных действий требуют проверки.
При пустом уточняющем проходе исходное наблюдение сохраняется с предупреждением.

### Удостоверение и банкнота

Для заявлений о наличных выполняется ограниченный
отдельный локальный вопрос о типе предмета, без передачи ему первоначального
cash-описания. Из исходного видео повторно выбирается один кадр, до 640
пикселей по длинной стороне (без искусственного увеличения малого оригинала).
Это второй вызов той же Qwen, не независимый детектор и не калиброванная проверка.
Если изображения мелкие/размытые/смешанные, требуется unknown, а не догадка.
Удостоверение/бумага меняют cash_transfer на document_transfer, неясная передача
становится object_transfer. Неподтверждённый cash_left_unattended становится unknown;
если предмет оказался документом или отсутствует, cash_left_unattended удаляется.
При переклассификации убираются исходные неподтверждённые упоминания денег.
Тип предмета внутренний: публичные поля Observation не изменены.

verify_objects=True по умолчанию, verification_frame_side=640. На одно видео
не более max_object_checks=3 дополнительных запросов, каждый с кооперативным
лимитом object_check_seconds=6. Документы/неясные передачи не запускают второй
проход. При таймауте или исчерпании бюджета предмет остаётся неопределённым,
в warnings добавляется технический счётчик. При выключении
проверки предмета cash-кандидаты не считаются подтверждённой наличностью.
Дополнительные вызовы расходуют общий бюджет 300 секунд; скорость нужно измерить
заново. OCR личных данных/распознавание личности не выполняются и не запрашиваются.
Обычный вход/выход, сидение/печать, no cash action и предположения о намерении
отсеиваются промптом и ограниченным текстовым фильтром. Фильтр может пропустить
новую формулировку или убрать сложную фразу: это не гарантия качества.

Основной ответ модели теперь компактен: максимум два события на окно,
только индексы кадров, категория, тип предмета и роли; до 160 новых токенов.
description формируется шаблоном категории и уточняется при переклассификации
предмета. Это убирает свободный рассказ и снижает риск обрезанного JSON,
но теряет детали и может пропустить третье действие в загруженном окне.
Поле confidence остаётся null. Ошибки окон имеют фиксированные диагностические
коды (invalid_json/json_token_limit/invalid_frame_index и т.д.), без исходного
текста модели. Техническая summary агрегирует эти коды.

`timing_resolution_sec` сообщает максимальный пробел между выбранными кадрами
и границами окна. Это оценка плотности выборки, не гарантия точности события.
Короткие действия между кадрами могут быть пропущены. Качество на реальных видео
и новых ракурсах ещё не измерено.

Бюджет по умолчанию 300 секунд включает холодную загрузку модели и декодирование.
При предварительном `engine.load()` загрузка проходит до задания; `model_load_sec`
у таких заданий равен 0. Иначе поле измеряет загрузку в рамках текущего вызова,
включая импорты. Это не историческое время загрузки предыдущего задания.
Проверка дедлайна выполняется между окнами, при декодировании и после каждого
сгенерированного токена. Это кооперативный лимит: загрузка модели, seek и текущая
операция CUDA могут его превысить. Строгий внешний лимит с очередью требует
отдельного процесса/контроля со стороны backend; здесь он не гарантируется.

## Проверки только на искусственных данных

Из корня репозитория, выбранным Python 3.12 из подготовленного `.venv`:

```powershell
python -B -m unittest app.inference.test_synthetic -v
python -B -m app.inference.synthetic --model-path C:\local\models\Qwen3-VL-2B-Instruct --report synthetic_report.json
```

Первый запуск создаёт временные MOV и проверяет декодер/pipeline с подменённой
моделью, без GPU. Второй создаёт временный MOV с движущимся квадратом и кругом,
запускает настоящую Qwen и сохраняет синтетический отчёт. Это проверка работы
программы, не оценка распознавания кассовых действий. Реальные данные этими
проверками не открываются. Результаты реального анализа не выводите в облачный чат.

## Сравнение нескольких окон на GPU

```powershell
python -B -m app.inference.benchmark_synthetic --model-path C:\local\models\Qwen3-VL-2B-Instruct --report benchmark_synthetic.json
```

Создаётся только искусственный MOV: 16 секунд, 1280×720, 10 FPS. Окна:
0–8, 6–14, 12–16 секунд. Сравниваются 4 и 6 кадров на окно при длинной стороне
до 448 пикселей. Модель загружается один раз; загрузка вынесена отдельно в отчёт.
Перед измерениями выполняется отдельный прогрев GPU-генерации. Затем настройки
чередуются: 4, 6, 4, 6 кадров. По два измерения на конфигурацию: это предварительная
оценка, не статистический бенчмарк.
Уточнение отключено; его стоимость и качество нужно оценивать отдельно.
Отчёт содержит фактические PTS выборки и результат каждого прохода, а также
проверку явного timeout при заведомо недостаточном бюджете.
Проверяется также пустой список наблюдений на фигурах (отрицательный контроль).
Это не проверка распознавания настоящих кассовых действий.

## Локальная оценка по разметке

Команды batch inference и сравнения с форматом Айши, политика incomplete,
правила сопоставления и безопасное хранение результатов описаны в `EVALUATION.md`.
Модули `run_local` и `evaluate` не реализуют нормативные правила и не меняют backend.
Для текущего Excel с вердиктом и одним таймкодом предусмотрен отдельный
`evaluate_baseline` и инструкция `BASELINE_EVALUATION.md`; X-4/X-47 исключены
из его основных метрик как неоднозначная группа.

## Пробный пакет и техническая сводка без Rule Engine

`batch_tools prepare` интерактивно принимает два локальных MOV и исходные ID.
ID проверяются по нормализованному baseline_labels.json; нужны один нормальный
и один положительный эталон. X-4/X-47 отклоняются. Если файл переименован,
исходный ID указывает человек: содержимое видео для сопоставления не читается.
Видео нужно выбирать самостоятельно; класс известен по разметке и не определяется
по названию файла. Сохраняются именно ID из разметки, исходные файлы не меняются.

В пользовательском local_check.py добавлены prepare-batch, run-batch, summary.
Manifest и predictions каждого запуска получают новые имена; прежние результаты
не перезаписываются. Последний запуск выбирается через локальный last_run.json.

`batch_tools summary` считает только агрегаты статусов, времени и GPU по predictions.
При переданном manifest учитывает ожидаемое число видео и недостающие результаты.
Содержимое observations игнорируется. Пакетное wall time включает запуск процесса
и загрузку модели; per-video elapsed — только время вызова после загрузки.
Отсутствующие метрики имеют null и число доступных измерений. Это не измерение
качества обнаружения и не подтверждение полного SLA с правилами и backend.
