Inference: 2026.10.18.7. Правила: possible-signs-2026.10.18.1.
Это исходники новой версии, а не подтверждение качества на видео.
Рабочая ветка backend; commit и push не выполнялись.

## Что изменено

1. Добавлен отдельный каталог наблюдаемых признаков. Backend и локальный экспорт
   используют ASSESSMENT_MODE=possible_signs. Строгий режим сохранён для сравнения.
2. Inference выдаёт согласованные типы и проверяемые условия с временными доказательствами.
   Второй локальный проход повторно проверяет положительные условия, не получая первый ответ.
   Используется та же модель: это дополнительная проверка, не независимый эксперт.
   Бюджет контекстных проверок распределяется между разными категориями.
3. API, описание метода и диагностика согласованы с новым режимом. Приёмочный скрипт
   проверяет версию загруженного worker до отправки видео. Метрики учитывают также
   неопределённые результаты, чтобы F1 на решённой части не скрывал пропуски.

## Значение результата

- violation: есть подтверждённые моделью визуальные признаки для проверки человеком.
- no_violation: поддерживаемые признаки не обнаружены при завершённой обработке.
- Неопределённые условия не превращаются в no_violation. Без подтверждённого признака
  неразрешённые наблюдения пока дают failed по существующему внешнему API.
- Совпадение двух проходов модели не гарантирует правильное распознавание.
- Части признаков соответствует только визуальный чек-лист проекта. Обязательная
  норма для них не подтверждена. Связанные пункты НБРК указаны как контекст проверки,
  а не как доказательство применимости к конкретной ситуации.

## Ограничения покрытия

Все 20 пунктов сопоставлены категориям. В 17 пунктах есть хотя бы один автоматически
проверяемый визуальный признак — это не полное покрытие всех утверждений этих пунктов.
Пункты 1 и 5 (не было проверки личности/банкнот) остаются неопределёнными:
редкие кадры не доказывают отсутствие процедуры. Пункт 3 (возврат купюр) — нейтральное
наблюдение до выяснения причины. Включённый экран не означает распознанные данные клиента,
доказанную разблокировку или окончание смены. Принадлежность оставленных купюр не выводится.
Из 18 включённых записей каталога previous_cash_outside_storage требует непрерывного
доказательства, которое текущий sparse inference не выдаёт; новый признак
cash_on_desk_with_next_customer проверяет только видимое совместное присутствие.

## Конфигурация backend

```python
InferenceConfig(
    model_path=Path(config.MODEL_PATH),
    window_seconds=8.0, overlap_seconds=2.0, frames_per_window=4,
    max_frame_side=448, max_new_tokens=256, time_budget_seconds=300.0,
    refine=False, refinement_frames=6, check_relevance=False,
    max_service_checks=6, verify_positive_conditions=True,
    positive_check_seconds=8.0, max_positive_checks=6,
)
```

Модель создаётся и загружается один раз при старте worker. Сетевые AI API не используются.
Проверки ограничены общим бюджетом; достигнутый лимит не считается успешным полным анализом.
После согласованного прогона сравнить ошибки и долю определённых решений со старой версией,
а не только скорость. Уже использованные для настройки видео не называются независимым тестом.
