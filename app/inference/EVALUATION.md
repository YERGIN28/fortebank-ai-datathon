# Локальная оценка наблюдений

Для текущего open_labels.xlsx с меткой и одним таймкодом используйте
`BASELINE_EVALUATION.md`. Этот строгий evaluator требует дополнительной разметки
type/start_sec/end_sec и не подходит для текущего Excel без неё.

Сравниваются наблюдаемые события, не нормативные вердикты. Скрипт дополняет
работу Айши: её Rule Engine и финальные метрики нарушений здесь не реализуются.
Правила сопоставления ниже предварительные, их нужно подтвердить с Айшей.

## 1. Формат разметки

Один объект с `video_id` и `observations` — как в искусственном примере Айши.
Для нескольких видео: `{"videos": [объект_видео_1, объект_видео_2]}`.
В каждой записи нужны уникальный video_id и список observations (может быть []).
В событии обязательны type, start_sec, end_sec. Остальные поля, включая
observation_id, actors и confidence, для этой оценки не нужны и игнорируются.
Таймкоды должны быть конечными неотрицательными числами, start <= end.

Категории сравниваются как строки. demo_action_a из примера — вымышленная метка,
она не добавляется автоматически в допустимые категории Qwen. Сейчас inference
выдаёт cash_left_unattended/unknown до согласования полной таксономии.

Предсказания имеют те же video_id и observations плюс обязательный status:
complete, partial, timeout или failed. Для нескольких видео тоже videos-массив.
Это `result.to_dict()` с добавленным video_id. Идентификаторы назначаете вы,
они должны совпадать с разметкой; названия файлов скрипт по смыслу не сопоставляет.
Видео с неизвестными разметке ID и дубли ID отклоняются, чтобы не смешать выборки.

## 2. Запуск inference самостоятельно, локально

Не передавайте реальные файлы ассистенту. Не сохраняйте реальные предсказания
или разметку в Git, общую папку outputs Codex или облачно синхронизируемую папку.
Выберите отдельную локальную папку вне OneDrive, например C:\ForteBankPrivate.
Все команды выполняете вы на ноутбуке. Ассистент проверял только искусственные данные.

Создайте manifest.json в этой локальной папке:

```json
{"videos": [{"video_id": "synthetic_demo_001", "path": "synthetic_demo.mov"}]}
```

Здесь показаны вымышленные имена. В своём локальном manifest подставьте пути к
своим MOV и ID из разметки. Относительный path отсчитывается от папки manifest.
Существующий файл предсказаний не перезаписывается: выбирайте новое имя запуска.

Из терминала VS Code в корне репозитория:

```powershell
$inferencePython = 'C:\Users\Айсана\Documents\Codex\fortebank-local\.venv\Scripts\python.exe'
& $inferencePython -B -m app.inference.run_local --model-path 'C:\Users\Айсана\Documents\Codex\fortebank-local\models\Qwen3-VL-2B-Instruct' --manifest 'C:\ForteBankPrivate\manifest.json' --output 'C:\ForteBankPrivate\predictions_run1.json'
```

Модель загружается один раз. Настройки: 8 секунд, overlap 2 секунды, 4 кадра,
448 пикселей, 256 новых токенов, 300 секунд на вызов, refine=False.
Для отдельного экспериментального прохода можно добавить --refine.
Чтение аудио и распознавание личности не используются.

В терминал попадают только число завершённых видео и счётчики статусов.
Полные observations записываются только в указанный локальный predictions JSON.
После каждого видео результат сохраняется атомарно. При исключении одного видео
сохраняется failed и пакет останавливается: последующие ID будут missing.
Это предотвращает повторные обращения к потенциально повреждённому CUDA worker.
Незавершённые partial/timeout сохраняются и пакет продолжает работу.
Код возврата 2 означает наличие неполных/ошибочных результатов, 1 — ошибку старта.
Если загрузка модели при старте не удалась, predictions не создаётся.

## 3. Сравнение с разметкой

```powershell
& $inferencePython -B -m app.inference.evaluate --truth 'C:\ForteBankPrivate\annotations.json' --predictions 'C:\ForteBankPrivate\predictions_run1.json' --report 'C:\ForteBankPrivate\metrics_run1.json'
```

По умолчанию совпадение требует одинакового type, а ошибки ОБЕИХ границ не более
2 секунд. Сопоставление один к одному, с максимальным числом допустимых пар.
Дубликаты не повышают TP: лишний прогноз считается FP. При нескольких возможных
парах предпочтение отдаётся близким границам, но суммарная ошибка не минимизируется.
Поэтому тайминговые метрики при неоднозначных событиях зависят от сопоставления.

Альтернатива: --match-mode iou --iou-threshold 0.3. Тогда одинаковые категории
сопоставляются при temporal IoU >= порога. Для двух точечных событий вместо IoU
используется --tolerance-sec (по умолчанию 2). Точка и интервал в IoU-режиме
не совпадают; в boundaries-режиме проверяются обе границы, как обычно.
Режим и пороги фиксируются в отчёте; их нельзя менять между сравниваемыми прогонами.

unknown совпадает только с unknown. Это совпадение неклассифицированных наблюдений,
не подтверждение категории правила. Их количество вынесено отдельно.

## 4. Как читать отчёт

Сначала coverage и evaluation_complete. partial/timeout/failed/missing НЕ
считаются пустыми отрицательными результатами: эти видео исключаются из метрик
событий и явно учитываются в покрытии. При неполном покрытии CLI возвращает 2,
но агрегированный отчёт сохраняется. Нельзя сообщать F1 без покрытия: исключение
трудных видео может искусственно улучшить результат.

Далее TP/FP/FN, precision/recall/F1, средние ошибки start/end и temporal IoU только
на совпавших парах. Неопределённые доли имеют null, а не искусственную единицу.
Нормальные видео с пустой разметкой учитываются в negative_videos; отдельно
считаются negative_videos_with_false_alarms. Полностью пустая выборка событий
не даёт осмысленного event F1.

Среднее/максимальное elapsed и пики PyTorch считаются по доступным полям
предсказаний, включая неполные статусы. Загрузка модели до заданий, очередь,
Rule Engine и backend в эти времена не входят. Это не подтверждает общий SLA.

Отчёт не содержит video_id, описаний, путей видео, участников, кадров и пар
совпавших событий. Если решите передать что-либо ассистенту, передавайте только
агрегированный metrics JSON после собственной проверки его содержимого.
Программа не использует сеть и не читает видео при выполнении evaluate.

## Безопасные тесты

```powershell
& $inferencePython -B -m unittest app.inference.test_synthetic app.inference.test_evaluate -v
```

Все входы тестов искусственные. Тесты evaluator не требуют GPU или загрузки Qwen.
