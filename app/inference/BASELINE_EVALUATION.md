# Оценка по текущему Excel: вердикт и один момент

Для последнего пробного пакета local_check.py evaluate автоматически передаёт
manifest из last_run.json. Эталоны выбираются по запланированным ID этого пакета,
а не по ID успешных предсказаний: отсутствующие ответы остаются missing.
Лишние прогнозы вне выбранного manifest отклоняются, не подмешиваются в расчёт.
Команда local_check.py select-labels позволяет заранее сохранить локальный
baseline_labels_batch_*.json только для этих ID. Полная разметка не изменяется.
Сами результаты правил всё ещё нужны для запуска evaluate.

Зафиксированные значения verdict: violation / no_violation / needs_review.
needs_review — отказ от окончательного решения, не нарушение и не норма.
Такие записи отдельно учитываются в primary_coverage.needs_review и исключаются
из бинарных и временных метрик. Вместе с F1 обязательно показывать decision_fraction
(долю основной выборки с завершённым бинарным решением). Это предотвращает
представление метрик только на решённых случаях как качества на всей выборке.
У mixed-результата violation для локализации используются только элементы
со status=violation; элементы needs_review не подтверждают попадание в таймкод.
При needs_review CLI сохраняет отчёт и возвращает 2: бинарная оценка неполная.

Уточнение Айши принято: тип и обе границы пока не размечены. Для open_labels.xlsx
используется отдельный evaluate_baseline. Строгий evaluate с совпадением type и
обеих границ ±2 секунды остаётся целевым после дополнительной разметки.
Из одного таймкода НЕ создаются искусственные start/end или выдуманный type.

## Что сравнивается

Эталон: видео → verdict violation/no_violation и timecode_sec у положительных.
Прогноз: финальный результат Rule Engine, а не наличие observations от Qwen.
Формат одного прогноза:

```json
{
  "video_id": "synthetic_demo_001",
  "status": "complete",
  "verdict": "violation",
  "violations": [{"timecode_sec": 12.5}]
}
```

Для no_violation violations должен быть []. Для пакета используется videos-массив.
status — внутренний статус полноты анализа: complete/partial/timeout/failed,
а не внешний processing/done/failed. Backend сохраняет его вместе с вердиктом
правил. Отсутствующий verdict нельзя получить автоматически из непустого
списка AI observations: evaluator такое отклонит.

Метрики наличия нарушения считаются на уровне видео: TP/FP/FN/TN, precision,
recall, F1, accuracy. Отдельно считается hit по таймкоду: у положительного видео
хотя бы один найденный момент должен попасть в ±2 секунды от эталона.
Отрицательный прогноз для положительного видео — пропуск и для локализации.
Ошибка времени берётся до ближайшего предсказанного момента только на найденных
положительных видео; знаменатель этой ошибки указан отдельно.
Количество предложенных моментов тоже показывается: множество догадок может
искусственно улучшить ближайшее совпадение. Дополнительные моменты не объявляются
ложными событиями: единственный эталонный таймкод не является полной разметкой
всех событий. type/start/end в базовой оценке не используются.

## X-4 / X-47

По умолчанию вся неоднозначная группа X-4/X-47 исключена из основных метрик.
Она отдельно отмечается как ОДНА группа с числом исключённых записей и их
статусами. Вердикты/таймкоды для неё не оцениваются до разрешения неоднозначности.
Даже если выбран только один член пары, он остаётся исключённым. Сравнения
с эталонами этой группы не выполняются; разметка не переписывается.

Имена X-4.mov, X_4 и X4 сопоставляются одному ID. Две такие записи одного ID
внутри файла отклоняются. Прочие произвольные video_id сравниваются без учёта
регистра, но не связываются по содержимому видео. Файлы видео этот evaluator
не открывает и дубликаты по хешу не ищет.

evaluation_complete и coverage относятся к ОСНОВНОЙ выборке после исключений.
Статистика ambiguity должна передаваться рядом с итоговыми метриками, чтобы
исключённая неоднозначность не скрывалась. Partial/timeout/failed/missing также
исключаются из основных метрик с явным учётом покрытия, не считаются нормой.

## Локальное преобразование XLSX

Ассистент реальный Excel не открывает. В labels_xlsx используются стандартные
модули Python, без установки зависимостей. Нужно явно указать заголовки столбцов,
положительную/отрицательную метки и формат времени. Ниже только вымышленные имена:

```powershell
python -B -m app.inference.labels_xlsx --input 'C:\ForteBankPrivate\labels\open_labels.xlsx' --output 'C:\ForteBankPrivate\labels\baseline_labels.json' --id-column 'Clip' --label-column 'Flag' --time-column 'When' --positive-label 'YES' --negative-label 'NO' --time-format seconds
```

ВНИМАНИЕ: эти заголовки — пример, не утверждение о структуре open_labels.xlsx.
На ноутбуке Айсаны папка проверки — C:\Users\Айсана\Documents\ForteBankPrivate,
а Python — подготовленный Python 3.12 из fortebank-local/.venv.
Заголовки и формат текстовых секунд уже подтверждены пользователем;
готовый local_check.py convert-labels использует их без чтения исходника ассистентом.

Первая непустая строка — заголовок; используется первый лист или указанный --sheet.
seconds: числовые секунды; clock: MM:SS / HH:MM:SS; excel-time: доля суток <1.
seconds-text: секунды с необязательным русским суффиксом секунда/секунды/секунд;
допускаются десятичная точка или запятая. Например, полностью вымышленное
значение `123 секунда`. Минуты, отрицательные числа и произвольный текст отклоняются.
duration-text дополнительно поддерживает минуты и минуты с секундами:
вымышленное `2 минуты 15 секунд` преобразуется в 135 секунд. Поддерживаются
мин./сек. и дробные секунды. Диапазоны и неоднозначные записи отклоняются.
local_check.py convert-labels использует duration-text для смешанного формата.
Стили Excel автоматически не интерпретируются. Метки сравниваются точно, без
догадок о значении 0/1 или Да/Нет. Формулы и ячейки ошибок отклоняются;
нужна отдельная копия со значениями. Исходный XLSX не изменяется. Новые выходные
файлы не перезаписываются, приватные строки в терминал не выводятся.

Результат:

```json
{"videos": [{"video_id": "synthetic_demo_001", "verdict": "violation", "timecode_sec": 12.5}]}
```

## Запуск базовой оценки

```powershell
python -B -m app.inference.evaluate_baseline --truth 'C:\ForteBankPrivate\labels\baseline_labels.json' --predictions 'C:\ForteBankPrivate\results\rule_predictions.json' --report 'C:\ForteBankPrivate\results\baseline_metrics.json'
```

Вспомогательный local_check.py теперь использует evaluate для этой базовой
оценки и ожидает файлы baseline_labels.json и rule_predictions.json.
Для строгого сравнения дополнительно размеченных наблюдений есть evaluate-strict.
После подтверждения заголовков добавлен convert-labels: он использует столбцы
`наименование файла`, `таймстемп`, `нарушение / без нарушения`, метки
`нарушение` / `без нарушения` и duration-text. Исходный файл должен находиться
в локальной папке labels/open_labels.xlsx. Реальные строки ассистент не читает.
run по-прежнему сохраняет только AI наблюдения: вывод Rule Engine он не создаёт.
Нужно подключение правил со стороны Айши/Ерасыла, прежде чем измерять качество
финального вердикта. В чужие модули этот этап изменений не вносит.

Отчёт агрегированный: без ID, реальных эталонных таймкодов, описаний, кадров.
Реальные XLSX/JSON и видео храните локально вне Git/OneDrive/Codex outputs.
