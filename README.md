# ForteBank AI Datathon

Интеграционная ветка `codex/integrated-pipeline`: backend, UI, локальный inference
и правила собраны в одном checkout. Веса и приватные видео в репозиторий не входят.

Основа исходников: `ai` на `3092f9e`, `backend` на `7b6d0d4`,
`feat/rules-evaluation` на `dcc124c`. Скопированы только исходники модулей;
чужие `venv`, pycache, веса и данные не переносились. Рабочие ветки команды
сохраняются отдельно. Интеграционные правки нужно проверять в этой ветке.

## Запуск на компьютере с GPU и загруженной моделью

Используйте Python 3.11 и уже проверенное CUDA-окружение Айсаны.
Из корня репозитория:

```powershell
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` задайте собственный `API_KEY` и абсолютный `MODEL_PATH` к локальным весам.
Запуск:

```powershell
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

`python` здесь должен указывать на подготовленное окружение с Qwen, а не на
системный Python. При необходимости замените его на полный путь:
`& 'C:\путь\к\окружению\.venv\Scripts\python.exe' -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1`.

Для свежей отдельной папки можно сначала получить именно общую ветку:

```powershell
git clone --branch codex/integrated-pipeline --single-branch https://github.com/YERGIN28/fortebank-ai-datathon.git fortebank-integrated
Set-Location fortebank-integrated
```

Если эта ветка уже открыта, достаточно `git pull --ff-only`. Не запускать второй
экземпляр Qwen одновременно с сервером.

`GET /health` должен вернуть `ready: true`. До загрузки модели приём файлов
отвечает 503. Веса во время обработки не скачиваются, используется локальный
Qwen. Ошибка запуска модели отображается в журнале worker и в health.
127.0.0.1 доступен только на этом компьютере; публичный адрес организует команда.

UI: `http://127.0.0.1:8000/`. API: `POST /api/v1/analyze`, multipart поле `file`;
затем `GET /api/v1/jobs/{job_id}`. Оба API-метода требуют `X-API-Key`.
UI обращается к серверным маршрутам без размещения ключа жюри в JavaScript.

## Путь результата

1. Один worker загружает модель один раз.
2. Inference проходит видео и возвращает наблюдения с исходными PTS.
3. Для `cash_left_unattended` выполняется отдельный локальный просмотр контекста:
   уход кассира и продолжение обслуживания в момент ухода.
4. Правила возвращают `violation`, `no_violation` или `failed` с причиной.
5. Backend извлекает 1–3 настоящих JPEG на событие из загруженного видео.

`Test violation` и искусственное ожидание удалены. В API нет `needs_review` или
поля `candidates`. Нерешённые наблюдения, частичный анализ, таймаут и ошибки
не превращаются в отрицательный вердикт. Подробности: [правила](docs/rule_decisions.md).

Принимается одно задание на GPU: пока оно занято, следующая загрузка получает 503.
Общий бюджет задания — 300 секунд от начала сохранения файла, проход inference —
240 секунд; остаток отведён контексту и JPEG. Генерация ограничена кооперативным
дедлайном. Зависший CUDA-вызов не прерывается принудительно: опрос API возвращает
`failed` после дедлайна, но worker может требовать перезапуска.

## Проверка без весов

Для CPU-проверки достаточно `fastapi`, `python-multipart`, `python-dotenv`,
`httpx`, `av==16.0.1`, `Pillow`, `numpy`; PyTorch не нужен.

```powershell
python -m unittest evaluation.test_decision evaluation.test_integration -v
python -B -m evaluation.check_all
```

Интеграционный тест создаёт искусственный MOV, подменяет только модель,
проверяет HTTP-загрузку, реальное декодирование, JPEG, схему и ошибки.
Это проверка соединения модулей, не качества Qwen на банковских видео.

## Что проверить перед сдачей

Дополнительный контекстный запрос новый: его качество и время ещё не измерены
на настоящих кассовых видео. Автоматически реализован один узкий тип по пункту 22
постановления НБРК № 231; остальные нормы не покрыты. `cash_left_unattended`
без подтверждения необходимых условий не считается автоматически нарушением.
Пустые наблюдения при полном проходе дают `no_violation` в пределах этого анализа;
полнота обнаружения всех возможных типов не гарантируется.

На GPU-хосте необходимо прогнать положительные и отрицательные настоящие видео,
оценить пропуски/ложные тревоги/долю `failed`, таймкоды, общее время до результата
и внешний доступ к обоим методам API. Проверки HTTP на fake-модели этого не заменяют.
