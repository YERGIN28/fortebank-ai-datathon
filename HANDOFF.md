## Что реализовано

Единый 401; очистка имени загрузки; сохранение JSON-контракта; отделённый demo
pipeline; один worker через lifespan; однократная загрузка AI внутри worker;
отказ startup при ошибке модели; межпроцессная блокировка для одной папки проекта;
последовательная очередь; внутренние timestamps; обработка ошибок и очистка файлов;
ограничение evidence до 3 кадров; чтение ключа клиентом из `.env`; команда запуска;
режимы fake/real; совместимые NumPy/OpenCV; ограничение huggingface-hub.

## Что ещё требуется от владельца Rule Engine

Текущий `evaluation.run_rules.process_video(video)` всегда возвращает
`verdict: needs_review`, `violations: []` и кандидатов, даже для полного анализа
без observations. Нужен согласованный механизм финального решения, включая
пустые observations, unknown и нормативные исключения.

Текст для передачи участнику (сообщение автоматически никому не отправлялось):

> Backend, UI и текущий AI объединены на локальной ветке backend. Подключён ваш
> существующий evaluation.run_rules.process_video. Сейчас он всегда возвращает
> needs_review. Для API жюри нужен согласованный финальный violation/no_violation
> и подтверждённые violations с timestamps для 1–3 кадров. Нужны правила обработки
> пустых observations, unknown и исключений. Подскажите финальный интерфейс и ветку.

До этого `real` является режимом проверки цепочки: complete → Rule Engine →
failed с пояснением. Демонстрационный fake по-прежнему выдаёт Test violation.
Этот факт нельзя представлять как готовность финального AI-сервиса.

## Проверенная среда и ограничения

Backend проверялся в отдельном Python 3.12.14. Исходное окружение пользователя
с PyTorch/CUDA не изменялось. Путь весов из локального `.env` существует;
загрузка Qwen и реальное GPU-распознавание в новой сборке пока не проверены.
Конфигурация AI сохраняет refine=False и остальные указанные параметры; новые
параметры актуального AI-модуля оставлены с настройками автора.

Публичный tunnel не настраивался. Jobs остаются в памяти. Штатное выключение
дожидается обработки очереди, поэтому может занимать время.

В исходной Git-истории отслеживается старый `venv/`; он не используется для
проверок и не включён в ZIP. Создавайте свежий `.venv` по README.
