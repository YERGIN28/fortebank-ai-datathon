# Изменения качества: 2026.10.18.6, кандидат для проверки

Статус: код и искусственные тесты проверены. Реальные видео на этой версии
не запускались: Айсана попросила сначала показать изменения.
Работающий сервис пока загружен с 2026.10.18.5; исходники не обновляют worker автоматически.

## Что меняется

1. Если первый контекстный проход подтверждает все наблюдаемые условия кандидата,
   включённая проверка `verify_positive_conditions` берёт шесть кадров вокруг
   исходного интервала с запасом по две секунды, размером до 640 пикселей.
   Второй запрос не получает первый ответ. Используется та же локальная Qwen;
   статистической независимости и калиброванной уверенности это не обеспечивает.
2. Положительные условия сохраняются только при повторном подтверждении.
   Противоречие, неполный ответ или нехватка бюджета оставляют `unclear`.
   Кандидат не исчезает и не становится отрицательным решением.
3. `object_handling` обозначает обычное видимое действие с предметом,
   материал которого не распознан. Это нейтральное действие, как `object_transfer`.
   `unknown` остаётся для неизвестной природы действия. Неопознанный предмет
   в кандидате на оставленные наличные по-прежнему не подтверждает банкноты
   и не снимает неопределённость.
4. Общий бюджет задания учитывает ожидание очереди и копирование принятого файла.
   Оставшееся время передаётся inference; после задания исходный config восстанавливается.
   GPU-вызовы прерываются кооперативно: жёсткий предел на уровне процесса не гарантирован.
5. Сервис временно предотвращает автоматический сон Windows, пока работает;
   постоянные настройки питания не меняются. Закрытие крышки и потеря питания отдельно не контролируются.
6. Необязательный `INFERENCE_AUDIT_DIR` сохраняет наблюдения только локально вне
   репозитория и API. Никаких пикселей или ответов модели в техническом stdout.
   `tools/quality_diagnostics.py` выводит только счётчики причин неопределённости.
7. Evaluator показывает долю обнаруженных положительных случаев среди ВСЕХ
   запланированных положительных видео, включая случаи без решения. F1 по одним
   завершённым решениям по-прежнему сопровождается покрытием.

## Точный config сервиса

```python
InferenceConfig(
    model_path=Path(MODEL_PATH),
    window_seconds=8.0, overlap_seconds=2.0, frames_per_window=4,
    max_frame_side=448, max_new_tokens=256, time_budget_seconds=300.0,
    refine=False, refinement_frames=6, check_relevance=False,
    verify_positive_conditions=True, positive_check_seconds=8.0,
    max_positive_checks=3,
)
```

Остальные значения — defaults `InferenceConfig`: object verification до трёх
вызовов по шесть секунд; основной контекст до трёх вызовов по десять секунд.
Лимит дополнительной проверки общий на видео: максимум три вызова по восемь
секунд, внутри общего бюджета. Это не включение всех правил.

## Что пока не исправлено

- Десять категорий правил остаются review_only: отсутствуют проверенные
  условия применимости, процедуры или наблюдаемые подтверждения. Их нельзя
  активировать только переключением verified.
- Непрерывное отслеживание происхождения купюр не реализовано.
- Модель не устанавливает скрытую блокировку компьютера, завершение смены,
  отсутствие проверки удостоверения вне ролика или подлинность денежных знаков.
- Разметка содержит бинарный флаг и один момент. Полноценные event precision/recall
  с точными типами и границами по ней не вычисляются.
- Дополнительная проверка может уменьшить ложные срабатывания ценой большего
  числа отказов. Улучшение нужно измерить; код сам по себе этого не доказывает.
